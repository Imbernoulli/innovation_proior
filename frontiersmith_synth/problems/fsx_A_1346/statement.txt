# Corner Patrol: Dismantling a Graph to Trap an Evader

## Problem
An evader hides on some vertex of a connected graph `G` and can retreat to any
currently-untouched vertex adjacent to its hideout. You do not chase it turn by turn;
instead you must submit a **complete elimination certificate**: a full order in which
every vertex except one final "refuge" vertex is struck off the map, together with, for
every struck vertex `v`, the set of *currently still-live* vertices you station pursuers
on to guarantee `v` cannot be a safe hideout anymore. Stationing a pursuer set `S` at a
vertex `v` is a legal elimination step only if every escape route out of `v` is already
watched by someone in `S` — formally, using closed neighborhoods restricted to the
vertices still live at that moment, `N[v] ⊆ ⋃_{u∈S} N[u]`. A large `S` (e.g. every live
neighbor of `v`) is always safe but wasteful; a small `S` exploits that some of `v`'s
neighbors are already shadowed by others in `S`. This is the classical graph "corner"
domination idea generalized from one guard to a team.

## Input
```
n m
u_1 v_1
...
u_m v_m
```
`G` is simple, undirected, connected, 0-indexed, `2 <= n <= 300`, `n-1 <= m <= 6n`.

## Output
Exactly `n-1` lines, one per eliminated vertex (the one vertex you never list is the
refuge). Line `i`:
```
v k g_1 g_2 ... g_k
```
meaning: at this step you eliminate vertex `v` (not eliminated before), guarded by the
`k` distinct vertices `g_1..g_k` (each `!= v`, none eliminated yet).

## Feasibility
Process the lines in order, maintaining which vertices are still live (all live
initially). A line is valid only if:
- `v` is live and is not the sole live vertex remaining.
- `1 <= k <= (live count) - 1`, all `g_j` live, distinct, `!= v`.
- Domination holds: every currently-live neighbor of `v` in `G`, and `v` itself, lies in
  `⋃_j N_live[g_j]` (the closed neighborhood of each `g_j`, restricted to currently-live
  vertices).
Any violated line (out of range, wrong count of lines, repeated/unknown vertex,
domination failing, trailing tokens) scores this test **0**.

## Objective (minimize)
Each elimination step costs `k^2` — coordinating `k` simultaneous pursuers grows
super-linearly harder than watching with fewer. Your total cost is
```
F = sum over the n-1 steps of k_i^2
```
Minimize `F`. Throwing every live neighbor at each vertex is always feasible but
quadratically expensive; finding a smaller certifying guard set at each step — by
noticing which neighbors are already shadowed by others — is what actually pays off.

## Scoring
The grader builds its own reference certificate `B`: eliminate vertices from deepest to
shallowest in a fixed BFS tree from vertex 0 (deepest first, ties by index, root last),
guarding every eliminated vertex with **all** of its currently-live neighbors (always
valid, never exploits redundancy). Let `B` be that certificate's total cost (always
`> 0`). Your score on a test is
```
ratio = min(1, 0.1 * B / max(1, F))
```
averaged over 10 tests.

## Constraints
- `2 <= n <= 300`, `n-1 <= m <= 6n`. Time limit: 4 s. Memory: 256 MB.
- Deterministic: identical output always yields an identical score.

## Example
Input (a 4-cycle plus one pendant):
```
5 5
0 1
1 2
2 3
3 0
0 4
```
Output:
```
4 1 0
1 2 2 3
2 1 3
3 1 0
```
Step 1: eliminate vertex 4 (leaf) guarded by `{0}` — valid (`N[4]={4,0} ⊆ N[0]`), cost `1`.
Step 2: eliminate vertex 1, live neighbors are `{0,2}`; no single live vertex covers
both (0 and 2 are not adjacent), so guard `{2,3}` is used: `N[1]={1,0,2} ⊆
N[2]∪N[3]={2,1,3}∪{3,2,0}`, cost `4`. Step 3: eliminate 2, guarded by `{3}` (its only
live neighbor now), cost `1`. Step 4: eliminate 3, guarded by `{0}`, cost `1`. Refuge is
vertex `0`. `F = 1+4+1+1 = 7`.
