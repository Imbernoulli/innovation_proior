The central puzzle is distinguishing interpolation from true rule learning. A small neural network can memorize any finite training set, including corrupted labels, so perfect training accuracy does not tell us whether the model has discovered the underlying rule. Natural datasets make this hard to isolate because the exact rule is unknown and train-test splits are entangled with distribution shifts. What is needed is a fully specified finite world where every possible query has a known answer, where train and validation are just disjoint cells of the same symbolic table, and where the input representation gives no notation shortcuts.

Existing ideas fall short in exactly this isolation. Random-label experiments show that networks can store arbitrary labels, but they do not create a setting where a discoverable rule predicts held-out cells. Double-descent and epoch-wise interpolation work show that longer training can improve generalization, but they typically vary capacity, noise, or natural-data complexity rather than fixing a tiny exact rule and watching what happens after the training set is already fit. Algorithmic benchmarks test symbolic procedures, but their emphasis is usually on architecture, length generalization, or unlimited generated data, not on the transition inside a fixed overparameterized model after memorization. The missing ingredient is a microscope that separates memorization time from rule-discovery time.

The method is Grokking. It builds a finite symbolic rule-learning testbed from complete binary operation tables and trains a small decoder-only transformer far past the point where training accuracy saturates. For a task such as modular division or permutation product, every element and operator is encoded as an opaque token. A random fraction of the table cells are revealed for training, and the remaining cells from the same table are held out. Each equation becomes a token sequence wrapped in end-of-sequence markers, `<|eos|> a op b = c <|eos|>`, and the model is trained to predict the right-hand side after the equals sign. Because the symbols are opaque, the model cannot exploit decimal digits or permutation notation; the only path to a held-out cell is through the pattern of interactions across the equations it has seen.

The signature I am testing for is a delayed generalization transition, and the design is built to make that transition legible rather than to assert it in advance. Training accuracy should become near-perfect within a small fraction of the full step budget, while validation accuracy stays at chance over that same window — read alone, that snapshot would label the model a memorizer. The claim worth testing is what happens if optimization continues far past that point, for orders of magnitude longer than the step count where training already looks solved: if delayed generalization is real, validation accuracy should eventually begin rising and climb toward the same near-perfect level training reached much earlier, with validation loss first rising while the model is confidently wrong on held-out cells and then undergoing a second descent long after training loss has already gone flat. Whether that late rise actually happens, and how long past the memorization point it takes to show up, is exactly what the long run is there to measure — a validation curve that stays flat instead would mean the memorizing solution is simply the end state.

Several planned probes are meant to test, not merely illustrate, the interpretation that the optimizer moves from a sharp memorizing solution to a flatter rule-like one. An intervention sweep at matched step budgets should show whether weight decay is the strongest single lever for reducing the training data needed to generalize, and whether minibatch or injected Gaussian weight/update noise point the same direction, consistent with a bias toward flatter regions. A label-corruption check is there to rule out the competing capacity explanation: if the network can still reach near-perfect training accuracy after a controlled number of training labels are replaced with wrong values, that would show it has enough spare parameters to memorize both the rule and explicit lies, so generalization cannot be explained by the model simply lacking room to memorize exceptions. A representation probe looks for a structural signature in the output-layer embeddings — a roughly circular arrangement for modular addition, coset clustering for symmetric-group operations — that would be hard to explain except as a recovered trace of the algebra. And a sharpness check, correlating a loss-sensitivity proxy against validation accuracy across fixed-time runs, is the quantitative version of the same story: a negative correlation would be the predicted signature if generalization only shows up once the weights have moved into flatter regions, and its absence would undercut that account rather than being something to explain away.

The training recipe for the main experiments uses a two-layer decoder-only transformer with width 128, four attention heads, causal masking, and about four hundred thousand non-embedding parameters. The optimizer is AdamW with learning rate 1e-3, betas (0.9, 0.98), epsilon 1e-8, linear warmup over ten updates, minibatch size min(512, ceil(train_size / 2)), weight decay 1, and up to 1e5 gradient updates for the reported learning-time curves. A dramatic modular-division demonstration uses 50 percent training data, Adam without weight decay, and 1e6 updates to make the late transition visible.

My own implementation builds this table with a routine I call `ArithmeticDataset.make_data`, wrapping each revealed or held-out equation as

```text
<|eos|> a op b = c <|eos|>
```

Every symbol in that line, including the operator and the equals sign, is drawn from one shared vocabulary of opaque tokens, so nothing in the surface form carries mod-`p` arithmetic or permutation notation. Training feeds every token except the final `<|eos|>` as input and takes the one-token-shifted sequence as the target; I compute loss and accuracy only on target positions that come after `=`, so a single row must predict both the answer symbol `c` and the trailing `<|eos|>`. The division tasks never call a modular-inverse routine at data-generation time: instead the generator enumerates the quotient `c` directly and renders the equivalent identity `(y * c mod p) / y = c`, which holds because `c = a * y^{-1} mod p` iff `y * c = a`.

The network itself is the two-block, four-head, width-128 decoder described above, with sinusoidal position encodings, a lower-triangular causal mask, ReLU feed-forward layers, no dropout by default, and no bias term anywhere in the attention, feed-forward, or output linear maps. What makes the optimizer worth spelling out is that it is not stock AdamW: the decoupled weight-decay step is applied before the Adam update itself, and it can decay either toward zero or toward the saved initial weights. I keep both modes as an explicit switch because they encode different priors on the flatter, rule-like solution I am chasing: decay-to-zero biases every parameter toward a low-norm solution regardless of where training started, while decay-to-initialization biases the parameters to stay near wherever they began. Which prior actually pushes the optimizer toward generalization sooner is a question for a matched-budget comparison, same data fraction, same step count, only the decay target flipped, and the mode that reaches high validation accuracy in fewer steps is the one worth keeping as the default:

```text
if weight_decay_form == "to_zero":
    p <- (1 - lr_t * weight_decay) p
elif weight_decay_form == "to_init":
    p <- p + lr_t * weight_decay * (p_init - p)

m_t <- beta1 m_{t-1} + (1 - beta1) g_t
v_t <- beta2 v_{t-1} + (1 - beta2) g_t^2
direction <- m_t / (sqrt(v_t / (1 - beta2^t)) + eps)
p <- p - (lr_t / (1 - beta1^t)) direction
```

When `noise_factor` is greater than zero I add Gaussian noise to `direction` before that final subtraction, which is the same injected-noise intervention the noise sweep above is designed to test. The signs make the two decay modes legible on their own terms: decay to zero shrinks every parameter uniformly toward the origin, decay to initialization instead pulls each parameter back toward wherever it started, and in both cases it is the Adam direction, not the raw gradient, that gets subtracted from the parameters at the end.
