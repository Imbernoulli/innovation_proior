I refer to this result here as Rice's theorem, and the question it answers is: does there exist a general algorithm that can determine whether the semantics computed by an arbitrary program has some property. Rice's theorem's conclusion is that, as long as this property is a nontrivial extensional property, no such general decider exists. By extensional, I mean the property only cares about the partial function the program actually computes or the language it recognizes, not the program text, variable names, implementation details, or the execution process within finitely many steps. By nontrivial, I mean the property is neither true for all program semantics nor false for all program semantics. Rice's theorem tells me that these two conditions together are already enough to embed the halting problem, and hence lead to undecidability.

To understand why this result is so powerful, I can first recall the halting problem. The halting problem says that there is no algorithm that always halts and is always correct that can, for an arbitrary program and an arbitrary input, decide whether that program halts on that input. The cleverness of Rice's theorem is that it no longer proves undecidability for one specific property at a time, but instead uniformly reduces the decision problem for all nontrivial semantic properties to the halting problem. This means that questions that look different on the surface — "does it accept the empty string", "does it recognize the empty language", "does it compute a constant function", "does it recognize a finite language" — all share the same undecidable root.

The core idea of the proof is very clean. Consider a nontrivial semantic property P. Because P is nontrivial, there exists a partial computable function g satisfying P, and there also exists a partial computable function not satisfying P. In particular, I can consider the everywhere-undefined function bottom, which never returns on any input. Because P is nontrivial, I can always choose g such that g and bottom have opposite truth values under P. Now suppose there exists a decider D for P that always halts and is always correct. Given an arbitrary halting instance, i.e. a program M and an input x, I construct a new program Q: Q, on input y, first simulates M(x); if M(x) halts, then it computes g(y) and returns it; if M(x) does not halt, then Q also never terminates. So Q's semantics has only two possibilities: if M(x) halts, Q is g; if M(x) does not halt, Q is bottom. Since g and bottom have opposite truth values under P, running D on Q is equivalent to deciding whether M(x) halts. But the halting problem is undecidable, so D cannot exist.

The power of this proof lies in its generality. I don't need to know what P specifically is, and I don't need to exploit the structure of a specific property like "accepts the empty string" or "recognizes a finite language" — I only need P to be able to distinguish two kinds of semantic behavior. It is precisely because of this generality that Rice's theorem unifies many seemingly-separate undecidability results into a single theorem. It reveals a deeper fact: undecidability does not come from the accidental complexity of some specific property, but from the expressive power of semantic judgment itself. A program's true input-output behavior is rich enough to hide an arbitrary halting instance.

At the same time, the boundary of Rice's theorem is also clear — it does not say that all questions about programs are undecidable. Syntactic properties are decidable, for example "does the program source contain a certain keyword" or "does the program use a certain particular variable name". Bounded-execution properties are also decidable, for example "can the program halt within 100 steps", because we only need to simulate 100 steps. Program analysis over specific sublanguages can also be effective, for example certain decision problems over regular expressions or context-free grammars. What Rice's theorem rules out are those problems that require deciding the true semantics for all programs, in particular nontrivial extensional properties that depend only on input-output behavior.

In the practice of automated program analysis and program verification, Rice's theorem tells me I cannot expect there to exist a general semantic decider that is both complete and always halting. Real tools must trade off between precision and computability: doing precise analysis on a specific subset of programs, giving conservative approximations, answering "unknown" when uncertain, or compressing an infinite semantic space into a finite abstract domain via abstract interpretation. All of these approaches work within the boundary that Rice's theorem draws.

Tightening the argument above into a precise theorem, together with spelling out the reduction step that actually does the work in the proof, is where this result should land — what needs to be proved here is the true semantic behavior of an arbitrary program over an infinite time scale, and any script that runs for some finite amount of time can only demonstrate the skeleton of the reduction; it cannot substitute for the proof itself.

Rice's theorem can be written as: let $\varphi_e$ denote the partial function computed by program index $e$, and let $P$ be a property on the set of partial computable functions satisfying nontriviality — there exists a partial computable function $g$ such that $P(g)$ holds, and there also exists a partial computable function $\bot$ (which can be taken to be the everywhere-undefined function) such that $P(\bot)$ does not hold, and $P$ depends only on $\varphi_e$ itself and not on the particular way the program $e$ computing it is written. Then there is no algorithm $D$ satisfying: for arbitrary $e$, $D(e)$ always halts, and

$$
D(e) = 1 \iff P(\varphi_e).
$$

The reduction the proof relies on can be written out fully as a constructive protocol, rather than staying at the level of description of "stuffing it into a new program". Take the pair $g,\bot$ above satisfying $P(g) \ne P(\bot)$. Given an arbitrary halting instance $(M,x)$, construct program $Q$:

$$
Q(y) = \begin{cases} g(y), & \text{if the simulation of } M(x) \text{ halts} \\ \text{(never returns)}, & \text{if the simulation of } M(x) \text{ does not halt} \end{cases}
$$

That is, $Q$ on input $y$ first simulates $M(x)$; as soon as the simulation halts it switches to computing and returning $g(y)$, otherwise $Q$ stays in the simulation stage forever. So the partial function $Q$ computes has only two possibilities: $\varphi_Q = g$ when $M(x)$ halts, $\varphi_Q = \bot$ when it does not. Hooking the hypothesized decider $D$ onto this construction gives

$$
D(\ulcorner Q \urcorner) = P(g) \iff M(x)\!\downarrow .
$$

This is because $D$ can always correctly decide $P$, so $D(\ulcorner Q\urcorner)=1$ if and only if $\varphi_Q$ has property $P$; when $M(x)$ halts this is equivalent to whether $P(g)$ holds, and when it does not halt this is equivalent to whether $P(\bot)$ holds, and $P(g) \ne P(\bot)$ makes these two cases completely distinguished by $D$'s output. So just by checking whether $D(\ulcorner Q\urcorner)$ equals $P(g)$, we get a decider for the halting problem that always halts and is always correct, which contradicts the undecidability of the halting problem; therefore $D$ does not exist, and Rice's theorem holds.

This theorem and this reduction protocol are the true output of this result: the protocol itself does not depend at all on the specific content of $P$, only on the single nontriviality condition $P(g) \ne P(\bot)$ — and this is exactly why it can cover all nontrivial extensional properties at once, unifying what would otherwise be an entire family of undecidability results proved property by property into the same reduction template.
