# @5 做法聚类 · 盲评标注协议 **v2**(不截断 / 四块)

与 v1 的差别只有两条:块从 8 个减到 **4 个(A-D)**,以及**每条答案都是全文,一个字没截**。
判「没产出方法」之前,请务必把该抽样**读完** —— v1 就是因为只给了前 4000 字,
把一堆长代码误判成了「半截代码、没有方法」。

你会拿到一个题目文件 `explore_blind2/<slug>.md`。文件里有 4 个互相独立的「块」(A-D),
每块是**同一个模型**对同一道题的 5 次独立抽样的最终答案。文件可能很大(最大约 200KB),
**要分多次读完,不要只读开头就下判断**。

块与块之间没有任何关系,**绝对不要跨块比较**,也不要猜哪个块是哪个模型。

## 对每一个块做什么

把它的 5 次抽样按「核心做法」聚成若干类:

- 同一类 = 核心算法思路相同。实现细节、常数、数据结构、变量名、代码长度不同**不算**不同做法。
- 不同类 = 机制不同。例如「模拟退火」vs「贪心 + 局部搜索」vs「动态规划」vs「束搜索」。
- **没产出可辨认方法的抽样**(空输出、只有废话、通篇自言自语的注释却始终没落地成算法、
  只有空壳函数 `pass`)全部归进**一个**类,并把该类的 `no_method` 设为 true。
  一个块最多只有一个 no_method 类。
- ⚠ **长 ≠ 没方法**。一条几万字的代码转储只要里面能看出核心算法,就是有方法;
  只有「从头到尾没落地成算法」才算 no_method。这是 v2 重标的唯一原因。

## 输出格式

一个 JSON 对象,键正好是 "A".."D",每个值形如:

```
{"n": <类数>, "clusters": [{"desc": "<一句话中文描述该类的核心做法>", "no_method": false, "samples": [1,2,3]}, ...]}
```

## 硬性约束(不满足会被判作废)

- 每个块里,所有 clusters 的 samples 合起来必须正好是 [1,2,3,4,5],不重不漏。
- `n` 必须等于 clusters 的个数。
- 4 个块一个都不能少。

写文件时只写 JSON 本身,**不要 markdown 代码围栏**。
