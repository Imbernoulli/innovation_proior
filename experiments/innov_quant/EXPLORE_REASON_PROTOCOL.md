# 「一条输出之内考虑过几条路」· 盲评标注协议

这份和 @5 那份(`EXPLORE_LABEL_PROTOCOL3.md`)不是一回事,别套用。
@5 问的是「5 次抽样之间有几种做法」;**这份问的是「一次抽样之内,模型考虑过几条路」**。

你会拿到一个题目文件 `explore_reason/<slug>.md`,里面有 6 个互相独立的「块」(A–F)。
每块是**一个模型**解这道题时 `</think>` 之前的**推理全文**,一个字没截。
**最终代码没有给你** —— 要判的是「考虑过什么」,看了答案会反过来倒推。
推理收尾处模型自己通常会说它最后选了哪条路。

文件可能很大(单题最大约 430KB),**要分多次读完,不要只读开头就下判断**。
块与块之间没有任何关系,**不要跨块比较**,也不要猜哪个块是哪个模型。

## 对每一个块做什么

列出这条推理里**真正认真考虑过的解法路线**,并标出每条最后有没有被采用。

什么算一条「路线」:
- 它是一个**能独立解这道题的完整思路**,例如「模拟退火」「贪心 + 局部搜索」「动态规划」
  「束搜索」「把它建成最小费用流」。
- 模型对它**做了实质推进** —— 算了复杂度、估了时间、想了数据结构、或者写了伪代码/片段。
- 同一条路线的参数、常数、实现细节、变量名不同,**不算**两条。

什么**不算**一条路线:
- 只在句子里带过一个名词而没有任何推进(「这有点像最大流」然后再没提过)。
- 对已选路线的调参、改常数、换容器、加剪枝 —— 那是同一条路的细节。
- 复读、自我怀疑、格式碎片。

每条路线记 `adopted`:
- `true` = 推理收尾时它是被采用的那条(或被采用方案的主体)。
- `false` = **考虑过又放弃**了。

一条推理正常会有 1 条被采用的路线;如果模型最后没定下来,可以 0 条 adopted。

## 输出格式

一个 JSON 对象,键正好是 "A".."F",每个值形如:

```
{"routes": [{"desc": "<一句话中文描述这条路线>", "adopted": true},
            {"desc": "...", "adopted": false}],
 "n_routes": <routes 的条数>, "n_abandoned": <adopted=false 的条数>}
```

推理是空的 / 通篇复读没有任何可辨认路线时,写 `{"routes": [], "n_routes": 0, "n_abandoned": 0}`。

## 硬性约束(不满足会被判作废)

- 键正好 "A".."F",6 个块一个都不能少。
- `n_routes` == `len(routes)`;`n_abandoned` == routes 里 `adopted` 为 false 的条数。
- `adopted` 为 true 的**最多 1 条**。
- 写文件时只写 JSON 本身,**不要 markdown 代码围栏**。
- **你自己把这几个文件标完,不要再派 subagent** —— 派出去的会看到整批指令、标到别人的题上。
