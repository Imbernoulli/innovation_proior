### 1.4 taste:`openreview_decide` 这个任务本身不可用(§21 的主张已撤回,见 §25)

> **⚠ 本节的主要主张已撤回。** 我把受控消融(2026-09-07)与 `_y26pp` 主跑(2026-09-15,
> 协议对齐之后)配对,混淆了「去掉会议名」与「换了协议」。用同世代的 `cc_idea32k_<arm>`
> (09-07,消融前六小时)重做后:**去掉会议名让每条臂都变好、base 变好得最少**
> (base −0.017、SFT −0.050、RL(base) −0.142、RL(01mix) −0.110),
> 「单调剂量-反应」和「base 靠会议名记忆拿分」**都不成立**。
> RL(01mix) − base 仍从 −0.071 变到 +0.022,但**两端 CI 都含 0**。
>
> **还站得住的只有一条,但它足够**:那句会议名不是无害的(两条 RL 臂各动 0.142/0.110,
> CI 不含 0),所以 **v1 的 `openreview_decide` 不是一把干净的尺子,论文应报 v2(无会议名)口径**。
> 另外这个任务在 n=120 上太吵——**base 自己两次跑批在同一批题上 AUC 差 0.097**,
> 与此处每一个效应同量级,所以这个任务上不该做任何逐臂结论。详见 §25。

以下为撤回前的原始记录(数字都是实测,错在配对):


`idea` 的 `openreview_decide` 是 taste 一族里唯一把聚合拉成负号的任务(9B −0.082、4B −0.075)。
它经不起检查。

先排除阈值解释:gold 构造上严格 50/50,逐侧拆开发现准确率**全掉在 REJECT 一侧**
(9B base→RL(01mix):REJECT 侧 0.583→0.423,ACCEPT 侧 0.767→0.763),即模型变宽容了。
用每题 5 抽样的「判 ACCEPT 比例」做与阈值无关的 AUC 复核——**没救回来**(dAUC −0.115
[−0.200, −0.039])。阈值假说被自己的检验推翻。

真正的原因写在 `idea_prep.py` 自己的注释里:**v1 的 prompt 里有会议名**("submitted to ICLR 2023"),
模型可以靠背各会议的录取率拿分而不读论文。那条注释断言「捷径对所有臂开放,所以不影响排名」——
这个断言只在各臂同等保留这份记忆时才成立,而 RL 恰恰会冲掉它。脚本里备好的受控消融
(`--venue-ablation`:同一批论文/id/标签,只换掉会议那一句)**早已跑过**:

| 臂 | AUC 有会议名 | AUC 去掉会议名 | 掉幅 |
|---|---|---|---|
| 9B base | 0.776 | 0.696 | **+0.081** |
| 9B SFT(01mix) | 0.760 | 0.717 | +0.043 |
| 9B RL(base) | 0.698 | 0.668 | +0.030 |
| **9B RL(01mix)** | 0.661 | **0.718** | **−0.057** |

掉幅按 base > SFT > RL(base) > RL(01mix) **严格单调**,我们的臂是唯一去掉会议名反而更准的。
对 base 的差距随之翻号:**9B RL(01mix) − base 从 ★−0.115 变成 +0.022**;
9B SFT − base 从 −0.017 变成 +0.021。4B 没跑受控消融,但 v1 内部只比同会议内的题对
(捷径同样消掉)指向一致:9B 由 −0.115 变 −0.005,4B 由 −0.069 变 **+0.010**。

去掉捷径后,**补上这一格的正是创新先验**:RL(01mix) − RL(base) = **+0.050**(有会议名时是 −0.037)。

**能写进论文的**:这一项上的负号是基准伪影,一句话的受控消融即可证明,且「谁在吃捷径」有单调的
剂量-反应。**不能写的**:去掉会议名后我们**显著**强于 base——+0.022 的 CI 含 0(120 题),
站得住的是方向一致与单调性。taste 一节应报 v2(无会议名)口径,并把这个对照作为
「该基准测的是记忆而非判断」的证据。

### 1.5 4B 上 RL 退化成「不作答」,先验挡住了——与完成率是同一个现象(§22)

`aaar_equation`(四选一公式推断)上 `rlv5_4b_base_s20` 有 **36.8% / 35.0%** 的抽样给不出答案,
其余 7 条臂全都 ≤0.7%。关键是它**答出来时准确率完全正常**(0.586 / 0.582,与 4B base 的
0.600 / 0.555 同档)——这不是变笨,是一个纯粹的不作答退化。先验那一支 0.005 / 0.003。

| | 答不出率 RL(01mix) − RL(base) | 95% CI | 先验更低 / 更高 |
|---|---|---|---|
| idea(v1) | **−0.363** | [−0.417, −0.310] | **94 题 / 0 题** |
| ideav2 | **−0.347** | [−0.400, −0.295] | **93 题 / 0 题** |

120 题里没有一题是 RL(base) 更愿意作答的,且在两个独立构建的任务版本上都复现
(v2 重洗了选项顺序,所以不是选项位置的伪影)。

**这与 §20.1 的完成率是同一件事**:FrontierCS/ALE 上 RL(先验) − RL(base) 的完成率
15/15 格全正、Stouffer Z=+18.19;这里是完全不同的 bench(无代码、无判题器、无 32k 截断)
上的作答率,差 35 个百分点。**RL 在 4B 上会坍缩成不产出答案,创新先验阻止了这个坍缩**——
现在有两块互相独立的证据。机制仍未知(§2.1 末尾的三个常见解释已逐条排除),不作解释。

反例照报:10 个 taste 任务格里先验那支 8 个更低、1 个持平、1 个更高
(`idea:openreview_decide` 0.063 vs 0.017)。`aaar_equation` 之外的格子绝对量都 ≤1.5%。

### 1.6 4B:先验带来的判断力只长在「评审看走眼」的题上,且集中在冷门论文(§23)

`judge3` 的 `impact_contrarian` 是专为分辨「独立判断 vs 模仿评审」造的:只保留**评审偏爱了
后来被引更少那篇**的题对。配对的 `impact_pair` 是评审与后世一致的那一半。

| 臂(对照 `base4b`,strict lens) | `impact_pair` | **`impact_contrarian`** |
|---|---|---|
| `4b_ft01mix_a10` | −0.67 [−2.32,+1.03] | +1.16 [−0.50,+2.87] |
| `rlv5_4b_base_s20` | ★ −1.86 [−3.45,−0.26] | −0.39 [−2.43,+1.66] |
| **`rlv5_4b_ft01mix_a10_s20`** | +0.05 [−1.75,+1.86] | ★ **+2.49 [+0.77,+4.31]** |

**评审有共识的地方不比 base 强,评审错了的地方才强。** 没有先验的 RL 臂在 contrarian 上是平的,
在 `impact_pair` 上还 ★ 掉了——**这一格是先验给的,不是 RL 给的**。
MIMICRY 间隙(acc(pair)−acc(contrarian),照抄评审的 oracle 是 100%/0%):
ours −2.76% vs base −0.32%,excess **−2.43% [−4.95,+0.03]**。

**不是认名论文**:把 lc_gap 卡在 [1.0,1.7] 后按赢家知名度劈开,增益集中在冷门那侧
(冷门 81.0% vs base 76.4% = **+4.6pp**;名论文只有 +0.9pp)——长在记忆帮不上忙的一侧,
与 1.4 里 base 靠 venue 记忆拿分正好相反。判题器正反判两次取一致,各臂 majority-agree 87.8–90.1%。
两个 lens 方向一致;penalise 下 `rlv5_4b_base_s20` 变成 ★ −2.44%,因为它 1.45% 的抽样
给不出 VERDICT(我们 0.35%)——**§22 的不作答退化在第三块 bench 上又出现一次**。

**不能说**:9B 上没有这个现象(contrarian −0.68,MIMICRY excess +1.10 方向反了),这是 4B 结果;
任务设计里「模仿者 <50%」那条线没分开任何一条臂(所有臂 78–83%),分开各臂的是 2.5pp 的边际;
`novelty_pair` 对所有臂都是掷硬币,不用。

| `base9b_v2c` | −1.262 | [−3.953, +1.662] |
| `lo32nm_a10` | +1.319 | [−1.741, +4.745] |
| `rlv5_lo32nm_a10_s20` | −1.665 | [−4.547, +1.259] |

| **`rlv5_4b_lo32nm_a10_s20`** | **+2.693** | ★ [+0.362, +5.033] |

`4b_lo32nm_a10` 的年份效应 +2.509 ★ 与它自己的复跑噪声 +2.085 ★ 几乎一样大、方向也一样,作废;

**FrontierCS**(信噪比更好:172 题、单格方差小)**12 条臂现已全部齐备**(2026-09-16 补完
`rlv5_ft01mix_a10_s20` 的 y2000),各 172 题:**5 正 7 负,符号检验 p≈0.77,方向上完全是平的**。

`rlv5_4b_ft01mix_a10_s20` **+0.169** [−1.109,+1.593],都贴着 0。

+0.003**——它从来只差一次抖动的距离,**那颗 ★ 本身就是个随机数**。何况这条臂自己的复跑噪声是

**第三把尺子(§24,数字已按 §26 更正)。** 分数重尾、信噪比差,所以换上手里最灵敏的行为指标再问一次——

附带发现:复跑噪声 14 格里 10 格同向(Z=+3.50),不是随机误差而是**未识别的批次效应**。

## 3. 方法学:本期最重要的两项产出

### 3.1 ★ 判据升级:CI 不含 0 不够,必须先量噪声底

此前的显著性判据是「逐题配对 bootstrap 的 95% CI 严格不含 0」。**§17 证明这个判据在 FCS-research 上不可靠**:
6 次同协议复跑对照里 2 次出 ★,也就是 n≈63 题时约有**三分之一**的假阳性率。

实测噪声底:

| bench / 样本量 | 逐题配对 CI 半宽 | 判据是否可靠 |
|---|---|---|
| FrontierCS,n≈172 题 | **±1.2 ~ ±1.4** | 可用,但小效应要对噪声底 |
| FCS-research,n≈63 题 | 很宽,6 次对照出 2 个 ★ | **不可靠** |
| judge3,n=500/500/300 | 窄 | 可靠 |

**更正一处旧记录**:§12 里写的「FCS 复跑抖动 ±0.5」是**臂均值**的抖动,不是逐题配对 bootstrap 的 CI 半宽;
后者才是判显著性用的,是 ±1.2~1.4。

**新规则**:能跑同协议复跑的地方就跑一条定噪声底;单个 ★ 必须同时过
(a) 噪声底、(b) 逐任务/逐题拆解、(c) 尺子有没有分辨力这三关。
本期的两个反例正好各占一条:§15 的 `aaar_equation` 单任务扛全场(过不了 b),
§16 的 `novelty_pair` 全臂掷硬币(过不了 c)。

### 3.2 四项评测口径修复 —— 其中 A、B 会让此前的数字不可比

**A. research 判题把模型自己的错算成基础设施故障。**
`frontiercs_research_cpu_eval.py:495` 是
`if any(m in low for m in _INFRA_MARKERS) or proc.returncode != 0`——后半句意味着模型代码把求值器搞崩
也算 infra,于是这些格子被**从分母剔掉**而不是记 0。修两处只读树写入权限
(`julia_env/lock.pid`、`problems/.../sql/output_ans` 改指向 `$D/rejudge_env` 下的可写副本)。
环境先自证:拿已判出 >0 分的 8 个格子重判,**8/8 全部复现非零**。
各臂 research 覆盖从 298–313/320 提到 **311–320/320**。

对 research 均分的影响:RL 臂补回来的几乎全是真分数(+1.0~+1.4),非 RL 臂补回来的一大半是 0
(+0.09 ~ −0.31)。**方向对 RL 有利,但不改变先验 vs base 的结论**:
9B SFT 阶段 ft01mix − base 旧 +1.26 → 新 +1.20;RL 阶段 rlv5_ft01mix − rlv5_base 旧 +1.99 → 新 +2.01。

**B. idea / taste / judge3 三个 bench 一直在协议外采样。**
把 RL 训练 rollout、RL validation、主 bench、MLS、gen_client、idea_client、judge_pairwise/pointwise
七条链路逐行追到实际构造请求那一行,唯一真正的不一致是 **`presence_penalty`**
(RL rollout 与主 bench 都发 1.5,这三个 client 代码里根本没这个参数;min_p / repetition_penalty
是靠服务端默认值巧合对上的)。

后果实测(同 parser、同 400 字窗口、逐格配对、n=960/臂,唯一变量是 presence_penalty):

| 臂 | strict-miss 无 pp | 有 pp | 每答 tokens |
|---|---|---|---|
| base9b_v2c | 0.5% | **0.0%** | 5950 → 4825 |
| ft01mix_a10 | 1.7% | **0.0%** | 6172 → 4694 |
| rlv5_base_s20 | 11.6% | **0.1%** | **8552** → 4467 |
| rlv5_ft01mix_a10_s20 | 17.7% | **0.2%** | **10369** → 4457 |

| rlv5_4b_ft01mix_a10_s20 | 23.2% | **0.5%** | **10856** → 3304 |

机制只出现在 RL 之后:**四条 RL 臂里三条,没有 presence_penalty 时生成长度爆炸到 8552–10856 tokens**
(非 RL 臂 4929–6172),`finish_reason=length` 也集中在这几条(119/192/332,非 RL 是 6–28)。
RL 策略本来就是在 `presence_penalty=1.5` 下优化出来的,拿掉这个惩罚去评测它就开始复读——
**问题在评测协议,不在模型。**

`rlv5_4b_base_s20` 不是这个机制(token 数几乎没动 2753→2859、`finish_reason=length` 本来就是 0),

修法:两个 client 加 `--presence-penalty`(默认 1.5)/`--min-p`/`--repetition-penalty`,
参数放置逐字照抄主 bench(presence_penalty 走顶层,其余走 `extra_body`);启动打印实际发出的协议供审计。
旧跑批以 `_y26sp` 标签原样保留、新的是 `_y26pp`,同 prompt 同 seed 可随时复查。

**两个本来很像问题、实测不是的**(记下来免得再翻案):`enable_thinking` 不是不一致
(Qwen3.5 template 默认开思考,不传 kwargs 与传 `True` 逐字节相同,只有 `False` 会插空 think 块);
idea 的 8192 上限不影响新跑批(`extra_bench_submit.sh` 里三家都已写死 `MAX_TOKENS=32768`)。

**C. 覆盖率修复。** 丢失率 FCS 1.01→**0.10%**、research 4.47→**1.02%**、ALE 1.50→**0.07%**;
