## 2. 评测协议(所有 bench、所有层完全一致)

`temperature=1.0, top_p=0.95, top_k=20, presence_penalty=1.5, max_tokens=32768, N=5, thinking on, year=2026`。

**`max_tokens=32768` 不是随便选的** —— 模型就是按 32K 最大输出长度训练的,评测预算必须等于训练长度。
用 8192 评过一次,AAAR 上的排名直接翻转(详见姊妹篇 §7.1)。

### 2.1 同分母

一道题只有在 **12 个臂上 5 个样本全部可用**(无 `error`、有数值分)时才计入。
任何一个臂缺一格,全体一起丢掉那道题 —— 代价是显式的。共同题数:

| bench | 共同题 / 总题 |
|---|---|
| FrontierCS | **152 / 172** |
| FrontierCS-research | **52 / 64** |
| ALE-40 | **39 / 40** |
| ALE-10 Lite | **10 / 10** |
| MLS-21 | **13 / 21**(8 臂口径,见 §5) |

### 2.2 @5 指标家族的含义

| 指标 | 含义 | 回答的问题 |
|---|---|---|
| `mean@5` | 5 次采样的平均分 | **平均水平**:随便采一次能拿多少 |
| `best@5` | 5 次里最好的一次 | **上限**:这题它到底会不会做 |
| `worst@5` | 5 次里最差的一次 | **下限 / 稳定性**:最差能烂到什么程度 |
| `pass@5` | 5 次里至少一次 > 0 的题占比 | **覆盖面**:多少题它能碰到边 |
| `5/5>0` | 5 次全部 > 0 的题占比 | **可靠性**:多少题它次次都能落地 |

聚合顺序是**先把一道题的 5 个样本压成一个数,再对题做自助**。
按样本自助会把同一道题的 5 个相关样本当成 5 个独立观测,区间会假性变窄。

### 2.3 `P(>0)` 是什么、不是什么

`P(>0)` = **自助重采样里差值为正的比例**。它**不是 p 值**,也不是"效应为真的概率"。

- `P=1.000` 只表示 10000 次重采样里没出现过非正的一次。
- 它**完全不覆盖训练 seed 方差** —— 每个臂只训练了一次,自助只在**题目**这一层重采样。
- 它**没有做多重比较校正**。本文件 + 姊妹篇一共报了上百个对比,期望里就该有若干个假阳性。
- 换算:`P(>0)=0.95` ↔ 双侧 p=0.10;**百分位 CI 不含 0 需要 `P>0.9749`**。

**★ 的定义**:本文件的 ★ 表示 **95% 百分位 CI 严格不含 0**(比"P>0.95"严一档)。
★ **未经多重比较校正**;全campaign 的 BH 校正结果见 `EVAL_REPORT_v2_9B_zh.md` §14.4。
注意有一类退化情形:某个指标上所有题的差值都恰好是 0(例如 research 的 `worst@5` 全为 0),
这时 `P(>0)=0.000` 但它不是"显著为负",本文件的 ★ 规则已经把这种情况排除掉。

主表(§3)由 `allstats.py` 生成,**5000** 次自助;配对表(§4)由 `pairprob.py` 同款算法生成,**10000** 次。

## 5. MLS-Bench(21 题,agent 多轮,×1 采样)

**先说结论:这张表里的小差距不可信。** 三条已查实的理由:

1. **18/140 个格子评的是同一个 tag 更早一次运行留下的 stale `is_final=true` 行** ——
   没提交的运行会去捡上一次的结果,系统性抬高"不提交次数多"的臂。
2. **46/140 次运行(33%)从头到尾没调用过 `submit`**,而 benchmark 没有自动提交兜底
   (`base.py:1658` 只做 `record_zero_if_no_finals`)。这正好对上 §1.1 里
   "reward 从没塑造过提交"这条 —— RL 大量练了"编辑",从没练过"交卷"。
3. 8 臂共同已评题只剩 **13/21**,分母太小。

口径:`llm-scaling-law-discovery` 和 `optimization-online-bandit` 不在协议内,已剔除;
只有 `status == scored` 算数(`timeout+scored` 是被饿死后强制记 0,不是测量;
`agent_failed` 是驱动在模型被问到之前就死了,没有数据)。

**MLS 的 0 分有三种,别混为一谈**:settings 为空 = 崩溃;settings 齐全但全 0 = 低于最差基线被钳到 0;
缺 `causal-learn`/`deap` 库 = 恒定丢 2 题。

顺带澄清一个我们自己曾经的误判:**"模型做出了更好的方案却不敢提交"是错的**,
已用 benchmark 自己的评分器证伪 —— `ml-clustering-algorithm` 上 ft03nm 的 DBSCAN 版重算 0.3322、
模板版 0.3875(逐位复现了 summary.json),**模板确实更好**,提交模板是对的。
而且 78 次有多版本可选的提交里,**74 次(94.9%)选中了自己最好的那一版**。

## 6. 覆盖率与已知的基础设施地板

这些缺口是**基础设施地板,不是模型表现**,而且同分母规则已经把它们从所有臂里一起剔除了。

| bench | 可用样本 | 未覆盖部分的原因 |
|---|---|---|
| FrontierCS | 836–860 / 860 | 零星超时 |
| ALE-40 | 197–200 / 200 | **只差 `ahc003` 一题** —— ALE-Bench 上游 bug,见下 |
| research | 300–311 / 320 | 每臂 10–19 行不可恢复:`symbolic_regression` 的 `precision_tol` 是确定性报错;`grammar_fuzzing` 要往只读目录写 `output_ans`;`vdb_pareto` 的 faiss 崩溃 |
| MLS-21 | 17–21 / 21 | timeout / agent_failed |

**`ahc003` 为什么不补(主动放弃,不是没做完)**

缺口精确到 **3 个臂 × 3 个样本 = 9 个样本**。它**已经自动重试过了** ——
三个臂上分别留下 8、8、13 条 error 记录才换来 3 个成功样本,即每个缺口重试三四次、次次失败。
根因在 ALE-Bench 上游 `src/ale_bench/data.py:543-544`:

```python
data_root = Path(tempfile.mkdtemp())
zf.extractall(data_root)
shutil.copytree(data_root / problem_id, data_root,
                copy_function=shutil.move, dirs_exist_ok=True)
shutil.rmtree(data_root / problem_id)   # <-- 这里抛 ENOTEMPTY
```

把子目录的内容 move 到它自己的父目录再删原目录,40 题里只有 `ahc003` 触发。
修它要动 `$FS/ALE-Bench`(只读)。补上它只能把分母从 39/40 变成 40/40,
而 ALE-40 上所有对比的 P 都在 0.27–0.77、CI 宽达 ±50~80 分,**多一道题不可能改变任何结论**。

## 8. 一页纸总结

| 问题 | 答案 | 证据强度 |
|---|---|---|
| RL 有用吗? | **有,而且很结实。** 四个起点、四个 bench、`mean@5`/`worst@5` 全部同向,多数 CI 不含 0 | 强 |
| RL 主要买到了什么? | **下限**。FrontierCS `worst@5` 四臂全部显著抬高,逐题几乎只赢不输 | 强 |
| SFT 单独有用吗? | **主 bench 上几乎没有。** 48 个 SFT−底座对比里只有 1 个跨线 | 强(零结果) |
| SFT 起点让 RL 更好吗? | **抹平了。** RL 后我们 vs 对照 48 个对比只有 1 个正向跨线(还有 2 个负向),`mean@5` 全 ns | 强(零结果) |
| 那 `ft03nm` 的 FrontierCS `pass@5` +7.89pp 呢? | 真的,但**它和"减自己 RL 前"是同一个数字**(见 §4.3 的口径说明),且 BH 校正后不入选 | 弱 |
| MLS 上的排名可信吗? | **不可信**,三条已查实的口径缺陷,见 §5 | — |

**必须一起读的一句话**:本文件报了约 150 个对比,`P>0.95` 这个门槛下期望的假阳性就有若干个。
单独一个 ★ 不值得当真;值得当真的是**同一方向被多个独立臂或多个独立 bench 重复**的模式 ——
本 campaign 里符合这个标准的只有 §4.2(RL 的效应),没有别的。
